# Pac-Man — Ghosts! More ghosts!

## Description

A remake of the 1980 Namco arcade game **Pac-Man**, written in Python 3.10+
with `pygame` (only functions that have an MLX equivalent: window, image
loading/blitting, scaling, keyboard/mouse events, text rendering as images).

Goal of the project: build a complete, playable game with an object-oriented
and modular architecture, a configurable JSON file, mazes generated by an
external *A-Maze-ing* package, a persistent highscore system, a cheat mode
for the peer review, and a packaged build published on itch.io.

Features:

- main menu (play, highscores, instructions, exit) with an animated preview;
- 10 levels (configurable), the first one with a fixed seed, then random;
- 4 ghosts, one per corner, each with its own personality (see *Implementation*);
- `pacgum` pacgums spread over the corridors, 4 super-pacgums in the corners
  (on the ghost starts) that make ghosts edible;
- eaten ghosts respawn in their corner after a few seconds;
- level timer, lives, score, level and remaining time always visible;
- pause menu (resume / back to menu / quit);
- game over and victory screens with name entry for the top 10;
- cheat console for the reviewers;
- responsive window (everything is drawn on a grid scaled to the window).

## Instructions

Requirements: Python ≥ 3.10, `pip`, and the assigned A-Maze-ing package
(`mazegenerator`) as a wheel at the root of the repository.

```sh
make install          # pygame + the A-Maze-ing package (MAZE_PKG=<file.whl>)
make run              # python3 pac-man.py config.json
make run CONFIG=other.json
make debug            # same, under pdb
make lint             # flake8 + mypy (mandatory flags)
make lint-strict      # flake8 + mypy --strict
make clean            # caches, build/, dist/
make package          # itch.io build -> dist/pac-man-<OS>.zip
```

Usage: the program takes **exactly one argument**, a `.json` file:

```sh
python3 pac-man.py config.json
```

Every error (wrong number of arguments, missing file, not a `.json`, invalid
JSON, generator failure, missing sprite…) prints a clear message, never a
traceback.

### Controls

| Key | Action |
| --- | --- |
| Arrows / WASD / ZQSD | move Pac-Man |
| ESC | pause / resume (the pause screen has *QUIT* and *MENU* buttons) |
| N | skip the level (only when the `/level_skiper true` cheat is on) |
| I (menu) | instructions |
| T (menu) | cheat console |

### Cheat mode

Open the console with **T** in the main menu, type a command and press ENTER
(`/help` lists them). Values stay until the game is restarted.

| Command | Effect |
| --- | --- |
| `/god_pac true\|false` | invincibility (ghosts and time-out cost no life) |
| `/level_skiper true\|false` | press **N** in game to win the level instantly |
| `/freeze_ghost true\|false` | the ghosts stop moving |
| `/game_more_life <n>` | number of lives at the start of the game |
| `/speed_up <1-100>` | Pac-Man speed |
| `/game_time <minutes>` | time limit of each level |
| `/dead_anim true\|false` | no death animation / countdown after a hit |

## Configuration

The config file is JSON. Lines starting with `#` or `//` and `/* … */` blocks
are comments. Unknown keys are ignored. A missing or invalid value is
replaced by its default (or clamped to its limits) and a warning is printed
on stderr, then the game continues.

| Key | Default | Limits | Meaning |
| --- | --- | --- | --- |
| `highscore_filename` | `"scores_board.json"` | non-empty string | highscore file, relative to the config file |
| `lives` | `3` | 1 – 99 | lives at the start |
| `pacgum` | `42` | 0 – 100000 | pacgums per level (capped to the free corridors) |
| `points_per_pacgum` | `10` | 0 – 100000 | |
| `points_per_super_pacgum` | `50` | 0 – 100000 | |
| `points_per_ghost` | `200` | 0 – 100000 | |
| `seed` | `42` | ≥ 0 | seed of level 1 (0 = random) |
| `level_max_time` | `90` | 10 – 3600 | seconds per level |
| `pacman_speed` | `10` | 1 – 100 | tiles per second |
| `ghost_speed` | `7.5` | 1 – 100 | tiles per second (×0.6 when edible) |
| `frightened_time` | `7` | 1 – 60 | seconds ghosts stay edible |
| `ghost_respawn_time` | `5` | 1 – 60 | seconds before an eaten ghost comes back |
| `levels` (or `level`) | 10 × `{"width": 18, "height": 18}` | ≥ 10 levels, width/height 8 – 30 | maze size in cells, optional `"seed"` per level |

If fewer than 10 levels are given, default levels are added.

When the time limit is reached, Pac-Man loses a life and the timer restarts
(the level is not regenerated).

## Highscore

- Stored in a JSON file (`highscore_filename`), a list of
  `{"name": str, "score": int}`, at most 10 entries, best first.
- Loaded each time a scoreboard is displayed (main menu → highscores, and the
  small board on the left during the game) and saved at the end of a game,
  when the player validates a name.
- Robust: a missing file gives an empty board; an unreadable file or an
  invalid JSON prints a warning and gives an empty board; every invalid entry
  (wrong type, negative score, invalid name) is skipped.
- Names: 1 to 10 characters, letters, digits and spaces only (other keys are
  ignored while typing). Scores: non-negative integers.

Why a JSON file: it is human readable (easy to check during the review), needs
no extra dependency, and lives next to the config file so the packaged game
can write it (the bundle folder may be read-only).

## Maze Generation

Mazes come from the assigned package `mazegenerator` (class
`MazeGenerator`), used as-is:

```python
MazeGenerator(size=(width, height), perfect=False, seed=seed).maze
```

`maze` is a grid of cells where each cell is a 4-bit wall mask
(N=1, E=2, S=4, W=8; 15 = closed cell, used by the "42" pattern).
`src/tools.py` adapts it to the game (`generate_level` / `convert_maze`):

1. each cell becomes a 2×2 block of a `(2w+1) × (2h+1)` tile map (cell centre,
   walls between cells, pillars at corners);
2. closed "42" cells keep only the outline of their zone;
3. each wall tile gets a sprite (vertical, horizontal or one of the 4 corners)
   from its neighbours;
4. Pac-Man starts on the free cell nearest the centre, each ghost on the free
   cell nearest a corner;
5. a super-pacgum is placed on each ghost start, then `pacgum` pacgums are
   spread evenly over the corridors reachable from Pac-Man.

`PERFECT=False` makes loops, so there are no dead ends. Level 1 uses the
config `seed`, the other levels a random one. Any exception of the generator
is caught (`MazeError`), the game retries with a random seed (3 tries) and
otherwise goes back to the menu with a message.

## Implementation

- **Main loop** (`src/__main__.py`): 60 FPS, every screen has
  `handle_event / update / draw / enter / exit` and asks for the next screen
  through `moov_screen = [name, ready]` (`"re"` = next level on the same
  `Game` object, which keeps score and lives).
- **Responsive grid**: everything is positioned in grid units
  (`tools.grid`), the grid is scaled to the window size, so the window can be
  resized freely.
- **Movement**: characters move tile by tile, `ratio` (0 → 1) is the progress
  towards the next tile. Pac-Man can turn when the next tile in the wanted
  direction is free (with a small tolerance), or reverse instantly.
- **Ghost AI** (`src/ghost_ai.py`): one BFS distance field from Pac-Man is
  computed each time he changes tile and shared by the 4 ghosts. At each tile
  a ghost chases (min distance) when Pac-Man is inside its detection range,
  flees (max distance) when edible, otherwise wanders without turning back.
  The 4 `GhostProfile`s (range 24/16/10/6, randomness 5→35 %) give them
  different personalities.
- **Collisions**: rectangle collisions between Pac-Man and pacgums/ghosts.
- **Errors**: config errors → `ConfigError`, maze errors → `MazeError`, file
  errors on highscores → warnings, missing images → clear message and exit.

## General Software Architecture

```
pac-man.py            launcher: arguments, resource folder, calls src.__main__.run
src/
  __main__.py         run() (args + config), main loop, get_screen()
  config.py           load_config(): JSON + comments, validation, defaults
  panel_admin.py      Parameter: values shared by all screens (config + cheats)
  screen.py           Screen (base) → Menu, Game, Game_over, Score
  perso.py            CharacterOutline → Pac, Enemy ; Pac_gum, Grid_txt, Button,
                      Tchat (text input), Help (text window), Logo, Disp,
                      Scoreboard, Score_disp (HUD)
  ghost_ai.py         GhostProfile, GhostBrain, distance_field()
  tools.py            sprites, grid, highscores, maze conversion (generate_level)
sprite/, font/        assets
pacman.spec           PyInstaller spec ; packaging/ = launchers for the build
project_management/   project management documents
```

Relationships: `main` owns one `Parameter` and the current `Screen`. `Game`
owns a `Pac`, 4 `Enemy` (each with a `GhostBrain`), the `Pac_gum`s and the
HUD objects, and calls `tools.generate_level` (→ `mazegenerator`).
`Game_over` and `Score` use `tools.save_score` / `tools.load_scores`.

## Packaging / itch.io

`make package` builds `dist/pac-man-<OS>.zip` with PyInstaller (`pacman.spec`):
the executable, the assets, `config.json`, `INSTRUCTIONS.txt` and the
launchers `play.sh` / `play.bat` (they pass `config.json` as argument).
Upload it on itch.io as a *restricted / draft* page, for example with
[butler](https://itch.io/docs/butler/):

```sh
butler push dist/pac-man-Darwin.zip <itch-user>/pac-man:mac
```
